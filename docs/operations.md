# Operating Autolux

Start with `uv run autolux --prod`. Use `--check` for model, device, configuration
and SSH readiness within 60 seconds, or `--check-full` for builds, all tests,
backtest and simulation. Both leave outputs stopped. Stop a show with Ctrl-C or
`uv run autolux stop`.

The show restarts itself; nothing outside Autolux relaunches it. Each session ends with the
same clean shutdown (dashboard viewer, Starfire, then the Radius receiver), and the next one
starts on the current store with a fresh viewer:

- **Restart show** in the Config tab starts the next session at once.
- Any error that ends a running show (Starfire, Radius link, capture, a bug) restarts it after
  5 s, then 15 s, then 60 s for each further fault; a session that ran 10 minutes resets the
  wait. The log carries each fault's traceback. A failed teardown, a relaunch that fails to
  start, or a relaunch whose dashboard does not come back counts as a fault: a relaunched viewer
  waits up to 30 s for the old one's port, then the session faults so the backoff gives the old
  viewer more time. A first show that fails before its first health check passes (devices,
  configuration, a receiver or Starfire that is down) exits, since it needs the operator; a
  first show without a dashboard runs on with a warning.
- Ctrl-C, `autolux stop` or `--duration` (one deadline for the whole run) ends the session and
  exits. The stop flag is checked during the wait and before each relaunch, so `autolux stop`
  also ends a show waiting to restart. The process holds the controller lock throughout, so a
  second show cannot start in between.

Each session logs `[prod] session N starting: <run dir>` and keeps its logs and its `--report`
(written as `<run dir>/<report file name>`) in its own run directory. Before a relaunch the
controller confirms over SSH that the old receiver released the output PC's hardware.

## Health

The dashboard at `http://autolux.local:8765` groups playback, tempo, intent and effect
above the show timeline. Its controls post from the browser straight to the show's bridge on
TCP 8766 (there is no fallback through the dashboard), so the firewall must allow 8765, 8766
and UDP 5353; control is plain http only, as the bridge accepts only http origins and an https
proxy would break its CORS check. Transport charts retain five minutes of receiver buffer,
audio level, interruptions, lost/dropped audio frames, scheduling error and DMX
delivery. Counters appear as rates; missing reports and counter resets leave gaps.
The section decoder's confidence per section type is under **Section Confidence**;
**FX Effects** shows when each fixture group, and the drop strobe, can fire again, with the row
that last fired, readiest first; each bar fills live between polls.
Link, telemetry and hardware faults appear only when they need attention.

- **No link:** check receiver power, SSH access and TCP 19002. Heartbeats run every
  ten seconds; missing heartbeats end the session after thirty seconds.
- **Audio glitches:** capture overruns identify input-device pressure; RX underruns
  identify missing playback data. Lost frames and queue drops distinguish transport
  trouble from device failures. Device errors stop the session with an actionable log.
  Capture absorbs stalls up to 200 ms in its device buffer. A longer stall loses audio;
  the device timestamp measures the gap, which is filled with silence so the show delay
  stays exact, and the health line counts it as a capture resync. Three resyncs within
  10 s, or a gap or consumer stall the 500 ms capture queue cannot hold, stop the session.
- **Buffer drift:** the target is 500 ms to absorb Wi-Fi delivery bursts. Clock correction handles slow
  device-clock differences; repeated rebuffering indicates sustained stalls.
  Audio delivery-gap and signal-peak metrics distinguish delayed packets from silence.
- **Lighting unavailable:** inspect the Starfire process log, fixture patch and Lua
  autoloop, the selected DMX universe, and the receiver's Enttec connection.
- **Analysis degraded:** inspect the GPU fault and timing panels. Rhythm continues
  while the analysis worker recovers.

The 14-second show delay is applied once. RX jitter and audio-device buffering add
latency to audio and its watermarked lighting together. DMX scheduling lateness
measures software scheduling, not the physical response time of fixtures.

## Fixture patch

**Save patch** in the Config tab checks the edit against the store's revision and Starfire's
native `rig` check and the show-start check (autoloops and, under production, the Radius TX
universe), then replaces three files: `rig/room.rig.pb` (regenerated by the same export
as `autolux starfire export-rig`), the tracked `rig/room.mvr` (the same bytes, which a fresh
checkout seeds its store from) and last the store `.live/starfire/rig.mvr`, so a replace that
fails (a file lock) leaves the store the show reads unchanged. A stale revision or a rejected
rig writes none of them. Only the default store mirrors to `rig/`; a `--rig-store` elsewhere
saves only itself. Save leaves the two `rig/` files uncommitted, and the operator commits `rig/`
after a Save. Git never overwrites a dirty file: if the commit being checked out or merged has the
same `rig/` bytes as the current one, the dirty `rig/` carries over silently; if they differ, the
checkout or merge aborts. If `rig/room.mvr` already differs from the store when you save (a pull
or checkout brought another rig), the Save status warns that it replaced it.

A running show reads its rig once at login, so a saved patch reaches the lights only on the
next session. While the show runs an older rig, the Config tab says so beside **Restart show**,
which is enabled whenever a show runs (a second click within 5 s confirms it). The show shuts
down cleanly and starts again on the saved store; the lights go dark until it is back. Under
`autolux run` (not `--prod`) the button only ends the show.

A fixture is its MVR uuid, and its name is a label. Renaming a fixture, or swapping the names of
two, changes labels only: position, address, group and a running test stay with the uuid, so a
renamed fixture tests before a restart. Names stay unique because autoloops name fixtures by
label. A fixture added in Config gets a fresh uuid, which the show learns only after **Restart
show**; until then the Config tab does not test it.

The show runs one fixture test at a time, so two open dashboards share it: a test from one moves
or clears the other's. A test stays lit, through edits and with the window in the background,
until you turn it off, close or change the selection, leave the Config tab, pause or close the
page. The page re-sends it every 15 s; Starfire's 60 s dead-man only ends a test whose page
vanished. When the show drops it (standby, sound stop, restart) the page stops holding it rather
than relighting it.

A mover's test row also has **Sweep** and **Aim**, which move the head through the same logical
pan as the show, so yaw, mount and soft limits apply exactly as in a loop. Sweep: the beam should
pan between the soft limits, tilted to the focus point's elevation. Aim: the beam should pass
through the focus point; if it points elsewhere, the yaw or mount is wrong.

Focus point: the MVR focus point the fixture aims at; Aim points at it. A mover's Placement has a
**Focus point (mm)** row in scene coordinates. Until it is edited it shows the default, the
stage centre on the floor (the middle of the fixtures' plan bounding box, where every head without
a focus point converges), and the MVR has no FocusPoint; the first edit adds
one beside the fixture and points the fixture's Focus at it.

Edits reach the lit fixture instantly while testing; Save writes the patch; Restart show makes the
loops use it. Every test of a fixture carries the unsaved placement (Matrix, soft limits, inversion
and focus point), and an edit to it re-sends the lit test within 150 ms, so Aim and Sweep follow a
yaw, mount or focus change at once. The test carries the unsaved Address, Universe and Mode too, so
it lights the new slots in the new mode's layout and the old ones go dark; an address that leaves
the universe or overlaps a fixture where the show runs it, a universe the show does not output, or a
mode with other cells or fewer attributes is refused in the status line and the previous test
stays lit. Only the test sees the unsaved pose; the loops keep the rig the show loaded.

Tests pin no geometry from `rig/room.mvr`, so editing the patch never breaks one. Starfire's
tests use the generic stage `autolux/tests/data/generic_rig/stage.mvr` and `stage.rig.pb`; the
Python tests use the frozen copies `autolux/tests/data/room.mvr` and `room.rig.pb`. One test
checks that the committed `rig/room.rig.pb` is the export of `rig/room.mvr`, which a Save keeps
true, and that `rig/library` still supplies GDTF. Refresh the frozen pair, and the goldens built
on it, only to change what tests cover.

## Metrics and logs

Console logs show startup, lighting changes, a music summary every ten seconds,
and system health every thirty seconds or when its state changes. HTTP access logs
are suppressed; server errors and recovery messages remain visible.
Use `uv run autolux --prod --verbose` for beat, note and protocol diagnostics.

Prometheus scrapes `http://autolux.local:8765/metrics`; headless mode serves local
metrics at `http://127.0.0.1:8766/metrics`. Use
`docs/prometheus.yml` as a local scrape configuration, and point Grafana at that
Prometheus server if longer-term history is needed. Metrics use seconds, cumulative
counters and fixed endpoint labels. Stale endpoint data is unavailable, never zero.

`.live/current.json` identifies the latest session. Each session retains generated
configs, Starfire output (including embedded TX) and receiver SSH output. The receiver keeps its own session
logs under `%LOCALAPPDATA%\Autolux\runs`. No credentials are stored in the repo.
